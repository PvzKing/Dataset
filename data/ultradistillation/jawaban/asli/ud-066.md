Pendekatan
Kueri disusun dalam beberapa CTE yang masing-masing mengerjakan satu tahap:

1. `selesai` menyaring pesanan berstatus `'selesai'`, mengambil `bulan` dari `substr(tanggal, 1, 7)`, dan mengganti kota NULL dengan `'Tidak diketahui'` lewat `COALESCE`. Tabel pelanggan disambungkan dengan `LEFT JOIN`, jadi pesanan yang pelanggannya tidak ditemukan tetap terhitung.
2. `per_pesanan` menghitung omzet tiap pesanan dengan `LEFT JOIN` ke `item_pesanan`. Pesanan tanpa item tetap muncul, dan omzetnya diubah dari NULL menjadi 0 dengan `COALESCE`. Agregasi per pesanan dilakukan dulu agar penggabungan dengan item tidak menggandakan baris.
3. `agregat` menjumlahkan omzet dan menghitung `COUNT(DISTINCT pelanggan_id)` per bulan dan kota.
4. Pada SELECT akhir:
   * `DENSE_RANK()` per bulan menghasilkan peringkat padat.
   * `SUM() OVER (PARTITION BY kota ORDER BY bulan)` menghasilkan omzet kumulatif.
   * Pertumbuhan dihitung dengan self-join ke bulan kalender sebelumnya, yaitu `strftime('%Y-%m', bulan || '-01', '-1 month')`. Saya tidak memakai `LAG()` karena `LAG()` mengambil baris sebelumnya, bukan bulan kalender sebelumnya. Jika suatu kota tidak punya penjualan di bulan sebelumnya, `LAG()` akan keliru membandingkan dengan bulan yang lebih lama.

Window function memerlukan SQLite ≥ 3.25, yang sudah disertakan di semua rilis Python modern.

```python
import sqlite3

_SQL_LAPORAN = """
WITH selesai AS (
    SELECT p.id                                  AS pesanan_id,
           p.pelanggan_id,
           substr(p.tanggal, 1, 7)               AS bulan,
           COALESCE(c.kota, 'Tidak diketahui')   AS kota
    FROM pesanan AS p
    LEFT JOIN pelanggan AS c ON c.id = p.pelanggan_id
    WHERE p.status = 'selesai'
),
per_pesanan AS (
    SELECT s.pesanan_id,
           s.pelanggan_id,
           s.bulan,
           s.kota,
           COALESCE(SUM(i.jumlah * i.harga_satuan), 0) AS omzet
    FROM selesai AS s
    LEFT JOIN item_pesanan AS i ON i.pesanan_id = s.pesanan_id
    GROUP BY s.pesanan_id, s.pelanggan_id, s.bulan, s.kota
),
agregat AS (
    SELECT bulan,
           kota,
           SUM(omzet)                   AS omzet,
           COUNT(DISTINCT pelanggan_id) AS jumlah_pelanggan
    FROM per_pesanan
    GROUP BY bulan, kota
)
SELECT a.bulan,
       a.kota,
       a.omzet,
       a.jumlah_pelanggan,
       DENSE_RANK() OVER (PARTITION BY a.bulan ORDER BY a.omzet DESC) AS peringkat,
       SUM(a.omzet) OVER (
           PARTITION BY a.kota ORDER BY a.bulan
           ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS omzet_kumulatif,
       CASE
           WHEN b.omzet IS NULL OR b.omzet = 0 THEN NULL
           ELSE ROUND((a.omzet - b.omzet) * 100.0 / b.omzet, 1)
       END AS pertumbuhan
FROM agregat AS a
LEFT JOIN agregat AS b
       ON b.kota  = a.kota
      AND b.bulan = strftime('%Y-%m', a.bulan || '-01', '-1 month')
ORDER BY a.bulan, peringkat, a.kota
"""


def laporan_penjualan(conn: sqlite3.Connection) -> list[tuple]:
    """Laporan omzet bulanan per kota dari pesanan berstatus 'selesai'.

    Setiap baris berisi: (bulan 'YYYY-MM', kota, omzet, jumlah_pelanggan,
    peringkat, omzet_kumulatif, pertumbuhan).
    """
    return [tuple(baris) for baris in conn.execute(_SQL_LAPORAN).fetchall()]

```

Contoh pemakaian

```python
conn = sqlite3.connect(":memory:")
conn.executescript("""
CREATE TABLE pelanggan (id INTEGER PRIMARY KEY, nama TEXT NOT NULL, kota TEXT);
CREATE TABLE pesanan (id INTEGER PRIMARY KEY, pelanggan_id INTEGER NOT NULL REFERENCES pelanggan(id),
                      tanggal TEXT NOT NULL, status TEXT NOT NULL);
CREATE TABLE item_pesanan (pesanan_id INTEGER NOT NULL REFERENCES pesanan(id), produk TEXT NOT NULL,
                           jumlah INTEGER NOT NULL, harga_satuan INTEGER NOT NULL);
INSERT INTO pelanggan VALUES (1, 'Ani', 'Pontianak'), (2, 'Budi', NULL);
INSERT INTO pesanan VALUES
  (1, 1, '2025-12-10', 'selesai'),
  (2, 1, '2026-01-05', 'selesai'),
  (3, 2, '2026-01-07', 'selesai'),   -- selesai tanpa item
  (4, 2, '2026-01-08', 'batal');     -- diabaikan
INSERT INTO item_pesanan VALUES
  (1, 'Kopi', 2, 10000), (2, 'Teh', 1, 30000), (4, 'Gula', 5, 1000);
""")

laporan_penjualan(conn)
# [('2025-12', 'Pontianak',       20000, 1, 1, 20000, None),
#  ('2026-01', 'Pontianak',       30000, 1, 1, 50000, 50.0),
#  ('2026-01', 'Tidak diketahui',     0, 1, 2,     0, None)]

```

Kasus khusus yang ditangani

* Pesanan selesai tanpa item tetap masuk laporan dengan omzet 0, dan pelanggannya tetap dihitung.
* Kota NULL ditampilkan sebagai `'Tidak diketahui'`. Kota ini juga menjadi satu kelompok sendiri dalam perhitungan peringkat, kumulatif, dan pertumbuhan.
* Omzet seri dalam satu bulan mendapat peringkat yang sama, peringkat berikutnya tidak melompat, dan urutannya ditentukan oleh nama kota.
* Bulan yang bolong (kota tidak punya penjualan di bulan sebelumnya) menghasilkan pertumbuhan NULL, bukan perbandingan dengan bulan yang lebih lama.
* Omzet bulan sebelumnya 0 menghasilkan pertumbuhan NULL, sehingga tidak terjadi pembagian dengan nol.
* Pergantian tahun ditangani oleh `strftime(..., '-1 month')`, sehingga `2026-01` dibandingkan dengan `2025-12`.
* Pelanggan dengan beberapa pesanan dalam bulan dan kota yang sama hanya dihitung satu kali.
* Pesanan berstatus selain `'selesai'` diabaikan sepenuhnya, termasuk item-itemnya.

Indeks untuk tabel berukuran jutaan baris

```sql
-- Menyaring pesanan selesai tanpa memindai seluruh tabel. Indeks parsial lebih
-- kecil jika proporsi pesanan 'selesai' tidak dominan.
CREATE INDEX idx_pesanan_selesai
    ON pesanan (tanggal, pelanggan_id) WHERE status = 'selesai';
-- Alternatif tanpa indeks parsial:
-- CREATE INDEX idx_pesanan_status ON pesanan (status, tanggal, pelanggan_id);

-- Paling penting: kolom pesanan_id tidak otomatis terindeks. Tanpa indeks ini,
-- LEFT JOIN ke item_pesanan menjadi sangat lambat. Menyertakan jumlah dan
-- harga_satuan membuatnya menjadi covering index, sehingga SQLite tidak perlu
-- membaca baris tabel.
CREATE INDEX idx_item_pesanan_cover
    ON item_pesanan (pesanan_id, jumlah, harga_satuan);

```

Kolom `pelanggan.id` sudah berupa `INTEGER PRIMARY KEY` (alias rowid), jadi tidak perlu indeks tambahan. Agar indeks parsial benar-benar dipakai, literal `status = 'selesai'` di kueri harus persis sama dengan klausa `WHERE` indeksnya, dan kueri di atas sudah memenuhinya. Setelah membuat indeks, jalankan `ANALYZE` agar query planner punya statistik yang akurat. Jika laporan ini sering dijalankan pada data historis yang sudah tidak berubah, langkah berikutnya yang layak dipertimbangkan adalah tabel ringkasan bulanan yang diperbarui secara inkremental.
