Manajemen memori Python bekerja dalam dua lapis: reference counting sebagai mekanisme utama, dan garbage collector generasional sebagai pelengkap untuk menangani referensi melingkar.

### Reference Counting

Setiap objek Python menyimpan penghitung referensi (`ob_refcnt`). Penghitung bertambah saat referensi baru dibuat dan berkurang saat referensi dihapus. Ketika mencapai nol, objek langsung dibebaskan.

Contoh dan perhitungan:

```python
import sys

class Contoh:
    pass

obj = Contoh()                     # refcount = 1 (variabel obj)
print(sys.getrefcount(obj) - 1)    # Output: 1
# sys.getrefcount sendiri menambah 1 referensi sementara, sehingga hasilnya dikurangi 1.

lst = [obj]                        # refcount = 2 (obj + lst[0])
print(sys.getrefcount(obj) - 1)    # Output: 2

del lst[0]                         # refcount turun menjadi 1
print(sys.getrefcount(obj) - 1)    # Output: 1

del obj                            # refcount menjadi 0 → objek dibebaskan
```

Keterbatasan reference counting: ia tidak dapat mendeteksi siklus referensi. Jika dua objek saling merujuk, refcount keduanya tidak pernah nol meskipun tidak ada variabel luar yang menunjuk keduanya.

### Garbage Collector Generasional

Untuk mengatasi siklus, Python menyediakan `gc` yang mengelompokkan objek ke dalam tiga generasi: 0 (paling muda), 1, dan 2 (paling tua). Objek baru masuk generasi 0. Setiap kali generasi 0 dikoleksi, objek yang bertahan dipindahkan ke generasi 1; jika bertahan lagi, ke generasi 2. Generasi yang lebih muda lebih sering dipindai karena objek muda lebih mungkin menjadi sampah.

`gc.collect()` tanpa argumen menjalankan koleksi penuh (generasi 2). `gc.collect(0)` hanya memeriksa generasi 0. Statistik dapat dilihat dengan `gc.get_stats()` atau `gc.get_count()`.

### Kapan Memory Leak Tetap Terjadi

Garbage collector tidak menjamin semua memori selalu kembali ke sistem. Beberapa kondisi yang masih menyebabkan kebocoran:

1. **Finalizer yang membangkitkan kembali objek.** Sejak PEP 442 (Python 3.4), siklus dengan `__del__` umumnya dapat dikoleksi. Namun `__del__` yang “membangkitkan kembali” objek, misalnya dengan menyimpan `self` ke daftar global, membuat objek itu tetap hidup dan tidak dibebaskan. Objek seperti ini tidak masuk `gc.garbage`; sejak Python 3.4 daftar itu hampir selalu kosong, kecuali untuk siklus berisi objek ekstensi C dengan finalizer gaya lama (`tp_del`) atau jika `gc.DEBUG_SAVEALL` diaktifkan.

2. **Referensi yang tetap hidup secara tidak sengaja.** Objek disimpan di cache global, daftar panjang, atau struktur data yang tidak pernah dihapus. Secara teknis objek masih “reachable”, sehingga bukan sampah bagi GC, tetapi memori terus tertahan.

3. **Sumber daya eksternal tidak dilepas.** File, socket, koneksi database, atau memori yang dialokasikan oleh ekstensi C tidak otomatis ditutup hanya karena objek Python-nya dikoleksi. Diperlukan `close()` atau context manager.

4. **Ekstensi C yang tidak berpartisipasi dalam GC.** Jika ekstensi C menyimpan referensi ke objek Python tanpa memberi tahu GC, objek tersebut bisa tetap “hidup” meskipun sudah tidak dapat dijangkau dari kode Python.

5. **`gc.disable()` tanpa pengelolaan manual.** Jika collector dimatikan dan program menghasilkan siklus, memori siklus tersebut tidak akan pernah dikembalikan sampai `gc.collect()` dipanggil secara eksplisit.

### Contoh: Referensi Melingkar dan Pemeriksaan dengan `gc` serta `weakref`

```python
import gc
import weakref
import sys

class Node:
    def __init__(self, name):
        self.name = name
        self.partner = None
    def __repr__(self):
        return f"Node({self.name})"

print("=== Siklus referensi ===")
a = Node("A")
b = Node("B")
a.partner = b          # a → b
b.partner = a          # b → a  (siklus)

print("Refcount a:", sys.getrefcount(a) - 1)  # 2: variabel a + b.partner
print("Refcount b:", sys.getrefcount(b) - 1)  # 2: variabel b + a.partner

del a, b               # variabel luar dihapus, tetapi siklus masih saling merujuk
print("Setelah del, sebelum gc.collect():")
print("  gc.garbage:", gc.garbage)          # biasanya kosong
print("  gc.get_count():", gc.get_count())  # jumlah objek yang dilacak per generasi

# Memaksa garbage collector generasi 2
collected = gc.collect()
print(f"  gc.collect() mengoleksi {collected} objek")
print("  gc.garbage setelah koleksi:", gc.garbage)  # kosong jika berhasil

print("\n=== Menghindari siklus dengan weakref ===")
class NodeWeak:
    def __init__(self, name):
        self.name = name
        self.partner = None
    def __repr__(self):
        return f"NodeWeak({self.name})"

x = NodeWeak("X")
y = NodeWeak("Y")
x.partner = weakref.ref(y)   # weakref tidak menambah refcount y
y.partner = weakref.ref(x)   # weakref tidak menambah refcount x

print("Refcount x:", sys.getrefcount(x) - 1)  # 1 (hanya variabel x)
print("Refcount y:", sys.getrefcount(y) - 1)  # 1 (hanya variabel y)

del x, y
# Karena weakref tidak membentuk siklus kuat, objek langsung dibebaskan oleh refcounting
print("Setelah del tanpa gc.collect():")
print("  gc.garbage:", gc.garbage)  # tetap kosong
print("  gc.get_count():", gc.get_count())  # tidak ada penumpukan objek siklus
```

Pada contoh pertama, `gc.collect()` mengembalikan jumlah objek yang berhasil dikoleksi dan `gc.garbage` tetap kosong, menandakan siklus berhasil dibersihkan. Pada contoh kedua, penggunaan `weakref.ref` mencegah siklus kuat sehingga reference counting saja sudah cukup untuk membebaskan objek tanpa bergantung pada garbage collector.
